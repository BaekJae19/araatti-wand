# 완드 동작 측정 데이터

TinyS3 #4(`DC:54:75:EB:80:B4`, 자리 A 오른손)를 USB 로 꽂고 **완드 시리얼**을 녹화한 것이다.
동글 · 유니티는 거치지 않는다. 휘두른 사람은 한 명이다.

종류마다 10회씩 소리 내어 세며 했고, **숫자는 동작의 끝점**(세로는 다 내렸을 때, 가로는 옆으로 다 갔을 때,
찌르기는 팔을 다 폈을 때)에서 셌다.

## 줄 형식

맨 앞 숫자는 녹화를 시작한 뒤의 **PC 초**다. `@숫자` 는 완드 `millis()` 다.

| 줄 | 뜻 |
|---|---|
| `#MOTION Vertical  95ms 만에 발동  Y -352 Z +126  count 2  @58623` | 베기를 보낸 순간. `95ms` = 판정 창이 열린 뒤. Y · Z 는 회전(dps), 부호는 v2 부터 |
| `#MOTION 끝 221ms  128ms 앞당김  창 전체로는 Vertical 같음 …` | 그 창이 닫힘. 앞당김 = 보낸 순간부터 창이 닫힐 때까지(예전 방식은 닫힐 때 보냈다) |
| `#STROKE 끝점 발동 후 241ms  가장 빠름 발동 후 105ms ( 702)` | v2~v5. 끝점 = 휘두른 방향의 속도가 가장 빨랐던 값의 1/4 아래로 떨어진 순간 |
| `#MOTION Thrust 221ms … lin -1.50 +0.71 +0.94 …` | 찌르기. `lin` = 중력을 뺀 가속(G)의 축별 최대값, 부호 있음. X 가 칼 길이 방향 |
| `#MOTION drop …` | 버린 창. v5 의 `+방향` 은 찌르기 모양이었지만 방향 때문에 버린 것 |
| `R81342,10,-74,-11,-22,106,-4064` | 6차만. 센서 원값 약 200Hz — `R<millis>,gx,gy,gz,ax,ay,az`. 자이로 70 mdps/LSB, 가속 0.244 mG/LSB. 바이어스는 `#CAL` 줄 |

원값 줄과 `#MOTION` 줄은 같은 `millis()` 를 쓰므로 시각으로 맞춰 자를 수 있다.

## 펌웨어 판

저장소 `firmware/wand_tinys3`(2026-10-06~)는 **v6 에서 측정용 로그와 데이터 모으기 모드를 뺀 것**이다.
판정은 v6 과 같고, 로그 줄에는 `@millis` · `#STROKE` · `처음` · `최대가속` 이 없다. 데이터 모으기 모드를 다시 넣는 법은
`IotPlayerController.md` 7-15 에 있다. 녹화 도구는 `firmware/tools/motion_capture.ps1`.

| 판 | 바뀐 것 |
|---|---|
| v1 | 베기를 회전 350 을 넘는 **순간** 보냄 · 세기 255 고정 · 동작이 잡히면 20ms 차례를 안 기다리고 전송 |
| v2 | v1 + 측정 로그(`#STROKE` 끝점 · 회전 부호 · `@millis`) |
| v3 | v2 + **버린 창 뒤에는 쿨다운 없음** · 찌르기 `처음` · `최대가속` 로그 |
| v4 | v3 + **위로 올리는 세로만 문턱 450** · 회전 350 을 넘은 창은 찌르기가 아님 |
| v5 | v4 + **찌르기는 길이 방향 최대 가속이 − 인 것만** · 데이터 모으기 모드(`d` 켬 / `D` 끔) |
| v6 | v5 + **찌르기는 판정 창이 150ms 이상 이어진 것만**. 짧아서 버린 것은 drop 줄에 `짧음` |

## 라벨을 붙일 때

- **찌르기가 없는 구간**(세로만 · 가로만 · 세로 아래·위)에서 나온 찌르기 후보는 전부 가짜다.
- **찌르기만 한 구간**은 길이 방향 최대 가속이 − 인 것이 민 동작, + 인 것이 팔을 뺀 동작이다(10회마다 − 가 10건 안팎).
- **콤보**는 어느 후보가 진짜 찌르기인지 확실하지 않다.
- 방향은 #4 기준이다 — 세로 내려치기 Y−, 올려 베기 Y+, 밀기 X−. IMU 를 다르게 붙인 보드는 다를 수 있다.
